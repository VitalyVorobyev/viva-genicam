# Changelog

All notable changes to this project are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Changes that are merged but not yet released are listed under **Unreleased**
below. Each release series has its own file in [`changelog/`](changelog/); a
release opens with what to read before upgrading.

## [Unreleased]

### Added

- **QUISS hardware follow-up.** Native Studio quick controls, compact preview, corrected near-cap cadence and controls after a software reset passed short checks. Instrumented delivery probes locate small-ROI loss before the first consumer read; preloading NumPy avoided cold-import drops. See the [bench record](docs/hardware-rtvision-2026-10-26.md#studio-and-delivery-follow-up-2026-10-27) ([#226](https://github.com/VitalyVorobyev/viva-genicam/pull/226)).

- **A compact image preview while configuring a camera.** Expand **Image preview** in Studio's Features tab and start acquisition to check settings without leaving the tab. It shares the existing preview connection and remembers whether it is folded ([#225](https://github.com/VitalyVorobyev/viva-genicam/pull/225)).

- **Image-tab fast controls for older cameras.** Exposure, gain and frame rate resolve their legacy standard names and retain the camera's own units, ranges and access restrictions. Acquisition and exposure/gain appear above statistics ([#225](https://github.com/VitalyVorobyev/viva-genicam/pull/225)).

- **Native camera values in Studio.** Freeze one frame to inspect its original sample values, histogram and line profile, then save a PNG that preserves its bit depth. Bayer inspection uses the sensor mosaic; snapshots contain demosaiced colour. Remote capture requires unambiguous tight rows ([#220](https://github.com/VitalyVorobyev/viva-genicam/pull/220)).

- **Reopening a GigE camera.** `reopen_gige` rediscovers a camera by MAC, opens a fresh session and XML, and optionally restores a saved configuration with per-feature results. Cancelling an open releases any control already claimed ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).
- **Tested cameras.** The user guide records hardware runs and their evidence, including real-camera GenTL checks through Harvesters and the C consumer ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).

- **Exclusive access.** `Access::Exclusive` opens a GigE Vision camera with exclusive access (CCP `0x1`): while it is held, other applications cannot even read the camera. `viva-camctl` takes `--access control|exclusive|monitor` on every command that opens a camera, and Python `connect_gige(..., exclusive=True)`. On USB3 Vision, where one application opens a camera at a time, exclusive is what every open already is, and monitor is refused. An Allied Vision Manta G-125B granted it (CCP read `0x1`) and answered another application's READREG and READMEM with `ACCESS_DENIED` ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **Watching another application's stream from the command line.** `viva-camctl stream --monitor` and `bench --monitor` open the camera read-only and receive the multicast stream another application set up, starting and stopping nothing. On the Manta G-125B the monitor received 123 frames while the controlling `stream --mode multicast` received all of its 308 complete ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **Python discovery by address.** `vg.discover_ip(ip)` asks one camera directly, for one on a routed subnet that broadcasts do not reach, and `vg.discover(allow_broadcast_ack=True)` lets a camera configured for another subnet broadcast its answer, as `viva-camctl list --ip` and `--allow-broadcast-ack` do ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **A GigE Vision hardware smoke suite.** `crates/viva-genicam/tests/gige_hardware.rs`, `#[ignore]`d and selected by `VIVA_GIGE_IP`, runs the parts of the hardware test plan a test can judge against a real camera; see [CONTRIBUTING → Tests](CONTRIBUTING.md#tests). All 19 tests pass on the Manta G-125B ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).

### Changed

- **More startup headroom for frame delivery (SR-28).** The bounded GigE Vision and USB3 Vision delivery queue holds 16 completed frames instead of 4. QUISS hardware had already evicted eight frames while acquisition start returned; a 16-frame queue retained frame 1 in the short probes and tolerated a 3 ms consumer pause. It permits up to four times the queued payload memory and a longer pending-frame age; per-frame allocation and copying stay unchanged. GigE hardware was measured; USB3 behavior is covered by fake/queue regressions.

- **Lower acquisition overhead on Unix.** The GVSP receiver uses bounded socket reads and resend writes instead of polling before every packet; Windows retains readiness polling. Focused timeout and cancellation tests, a reproducible two-process benchmark, and Manta ROI measurements accompany the change. Frame allocation and the four-frame delivery queue are unchanged ([#222](https://github.com/VitalyVorobyev/viva-genicam/pull/222)).

- **macOS local-network permission.** Studio bundles now declare why camera and service access needs the local network. The troubleshooting guide distinguishes app permission from CLI access; the observed debug-bundle `Broken pipe` failure still needs a controlled hardware reproduction ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).

- **Distribution notices and licensing boundaries.** Release archives, Python distributions, GenTL sidecars and Studio bundles carry target-specific dependency notices. Packaging rejects private bench material and placeholder notices. The licensing review separates MIT code rights from unresolved A3 and EMVA questions ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).
- **Typed Studio commands.** UI command names, arguments and results now come from registered Rust signatures, so command drift fails type checks ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).

- **A predicate that cannot be read is not satisfied.** A `pIsImplemented`, `pIsAvailable` or `pIsLocked` whose register the camera refuses made `NodeMap::feature_state` treat the feature as implemented, available and unlocked; it now reports it not implemented, not available, or locked, as the GenICam Standard defines a predicate by the value it reads. The Manta G-125B gates its `Lens*` features on an inquiry register at `0x23000` that it answers with `INVALID_ADDRESS`; they are now not implemented, and the warning is logged once per feature instead of three times. `viva-camctl dump` names on stderr each node it could not read instead of leaving it out silently ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **A takeover is seen on a camera that does not name its controller.** After a write refused with `ACCESS_DENIED`, a camera without GVCP Capability's CCP-application bit is asked by claiming control again (`GigeDevice::holds_control`): the Manta G-125B, which reads CCP as `0x2` to every application, accepted the claim from the holder and refused it to another. A session stopped past the heartbeat timeout while another took control now reports `ControlState::Lost` at its next write; before, it stayed `Held` ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **Events are acknowledged as they arrive.** `EventSocket`, and with it `EventStream`, now runs a receive thread that acknowledges each message the camera sends as it arrives and queues its events for the application, up to `EVENT_QUEUE_CAPACITY` (1024); past that the oldest are dropped, logged and counted in the new `EventStats` (`EventStream::stats`). The acknowledgement used to wait for the application's read: an Allied Vision Manta G-125B sent an event twelve times to a reader a second late, held back the events behind it, and, left unread for ten seconds, delivered 44 of about 600 and an `EventOverflow` for the rest ([ADR-0033](docs/adrs/adr0033-event-channel-acknowledges-on-arrival.md), [#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).
- **`viva-camctl action` and `send_action` report a refusal.** A camera that answers an action command with an error status is listed in the new `AckSummary::refusals` (Python `AckSummary.refusals`) and named by `viva-camctl action`. The Manta G-125B, without action commands, answers `NOT_IMPLEMENTED` under the command's own opcode, which was ignored as an unrelated acknowledgement and reported as "acknowledged by 0 device(s)" ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).
- **A camera's reported tick frequency is its clock's slope.** `Camera::time_calibrate` (and `TimeSync::fit` given a frequency) now fits only the offset, as the median over the samples, and takes the slope from `GevTimestampTickFrequency`. Sixteen samples taken over GVCP fitted an Allied Vision Manta G-125B's 48 MHz clock at 48.46 MHz in one calibration and 47.76 MHz in the next, and frames mapped through `map_dev_ts` after the first drifted 9.5 ms a second from their arrival (14.3 s in 25 minutes); with the reported frequency they drifted 31 ms in 20 minutes, the camera's clock running about 26 ppm ahead of the host's ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).

### Fixed

- **Studio controls after remote recovery (ST-61).** A replacement session refreshes both the backend model and the UI's feature cache, restoring controls without a manual reconnect. A delayed replacement cannot undo a user disconnect ([#225](https://github.com/VitalyVorobyev/viva-genicam/pull/225)).

- **Studio preview cadence near its display limit (ST-60).** Deadline pacing avoids taking every second frame from a camera just above the preview rate; a long pause starts a fresh cadence. Encoding time no longer shifts each deadline ([#225](https://github.com/VitalyVorobyev/viva-genicam/pull/225)).

- **Remote feature-state queries.** The single-feature wildcard handler no longer replies to the reserved bulk-state endpoint, avoiding duplicate error replies and repeated `bulk`-is-not-a-node warnings during Studio polling ([#224](https://github.com/VitalyVorobyev/viva-genicam/pull/224)).

- **QUISS six-sensor control ownership.** RTVision_6L_DCAM_v2 reverses its primary-application IP/port register contents. Ownership now also accepts that layout when both complete values identify our socket, preventing false control loss during acquisition. The real-camera GenTL consumer also preserves compressed XML as a ZIP container. See the [hardware record](docs/hardware-rtvision-2026-10-26.md) ([#224](https://github.com/VitalyVorobyev/viva-genicam/pull/224)).

- **Remote padded images.** Services retain each row's padding and send its stride in image header v2 (API 7), so Studio preview and native capture use the correct rows. Odd packed and subsampled images retain their final pixel group. Update services and Studio together ([#221](https://github.com/VitalyVorobyev/viva-genicam/pull/221)).

- **A refused resend packet no longer cancels its neighbours.** A packet-specific unavailable answer previously closed the whole missing range, suppressing recovery and counting its neighbours as unavailable. Only the named packet now stops retrying; an all-previous answer preserves higher ids, with request history and budgets unchanged ([#219](https://github.com/VitalyVorobyev/viva-genicam/pull/219)).

- **GigE session recovery.** The service replaces the complete served handle after control loss or address/interface changes, refreshing XML and connection metadata together ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).
- **Stale control routes after FORCEIP.** An address-unavailable send reconnects the existing UDP socket before retrying, preserving its controller port and transaction ID; confirmation of the original link-local hardware failure remains open ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).
- **Studio test teardown and fallback access.** Fake-camera tests await socket shutdown before releasing their port lock; fallback command mapping honors imposed access limits ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).

- `viva-camctl list --allow-broadcast-ack` and `viva-camctl report` find a camera configured for another subnet on macOS: its broadcast acknowledgement reached the host but not the discovery socket, which was bound to the interface's own address. With broadcast acknowledgements allowed, discovery now binds the unspecified address and keeps the socket on its interface. Found on an Allied Vision Manta G-125B ([#215](https://github.com/VitalyVorobyev/viva-genicam/pull/215)).
- **`viva-camctl` logs go to stderr.** They went to stdout, so `viva-camctl dump --ip <CAM> > values.txt` wrote twelve `WARN` lines from the Manta G-125B into the file; stdout now carries only the data ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **Chunk mode on a GigE Vision 1.x camera.** With `ChunkModeActive` on, the Manta G-125B sends payload type `0x0005` (GigE Vision 1.x extended chunk data: an image leader, the image as the first chunk, and a trailer of payload length, Size Y and chunk layout ID), which the receive engine did not assemble, so the stream delivered nothing. Such a block is now an image with chunks, as `0x4001` is. `Camera::configure_chunks` with no selectors sets chunk mode alone on a camera with no `ChunkSelector`, as the Manta declares ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **An event the camera resends is delivered once.** A camera resends an event until it is acknowledged, and the acknowledgement goes out when the application reads it: the Manta G-125B (`GevMCTT` 100 ms) sent one `ExposureEnd` eleven times, request id 1 each, to a reader a second late, and each copy came back as an event. A copy with the same request id and the same bytes is now acknowledged and dropped; distinct events under one request id are each delivered ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- **An odd pixel count in a bit-packed format converts.** An Allied Vision Manta G-125B at 1291 × 963 in `Mono12Packed` sends ⌈pixels × 12 / 8⌉ bytes, stopping inside the last packing group that PFNC 2.4 §6.7 completes; `viva_pfnc::convert` (and with it `Frame::to_rgb8` and `viva-camctl stream --save`) refused every such frame as one byte short. A bit-packed image now needs only the bytes up to its last pixel's ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).
- **The frame rate is the camera's.** `StreamStats::avg_fps` and `avg_mbps` were measured when the application took each frame, so frames handed over in a burst — held back behind an older one that lost packets, or read late — read as thousands of frames a second (`viva-camctl bench` reported 10 742 fps for the Manta G-125B at 30.9). They are now measured from when each frame's last packet arrived ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).
- **An action command to a subnet's broadcast address is sent.** `viva-camctl action --destination 192.168.2.255` failed with `Permission denied` on macOS: the socket allowed broadcasts only to 255.255.255.255 ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).
- **`GevSCPSPacketSize`'s do-not-fragment flag is kept.** Setting a packet size wrote the size alone, and the packet-size probe left the flag its test packets set: an Allied Vision Manta G-125B, which stores the flag and read `0x400005DC` before the run, read `0x000005DC` after streams with `--packet-size` or `--auto`. A size is now written with the flags the register holds, and the probe puts the flag back as it found it ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).
- **A short GigE Vision `10Packed` image is refused.** GigE Vision packs two pixels in three bytes whatever their bits, so four `Mono10Packed` pixels take 6 bytes; the check for a partial last packing group counted ⌈pixels × 10 / 8⌉, 5, and `viva_pfnc::convert::unpack_u16` returned three samples from 5 bytes where it had refused them, and `to_rgb8` on a `BayerRG10Packed` image read past the end and panicked. The minimum is now the whole groups and a lone last pixel's two bytes, which still accepts the Manta G-125B's odd-count `Mono12Packed` frames ([#218](https://github.com/VitalyVorobyev/viva-genicam/pull/218)).
- `viva-camctl bench --monitor` reported its mode as `unicast` in `--json-out`; it says `monitor` ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).

### Run on hardware

- On the Allied Vision Manta G-125B (firmware 00.01.44.28514, GigE Vision 1.2): a command register clears by the first `IsDone` read (`UserSetLoad`, done 15 ms after the write); `WriteAround` registers (`BlackLevel`, `Gamma`, `StreamBytesPerSecond`) read back the value just written; a second application's claim and its writes are refused with `ACCESS_DENIED` while one holds control, and writes from an application without control are refused while nobody holds it; a saved configuration loads back to the same 98 values; every pixel format it offers (`Mono8`, `Mono12`, `Mono12Packed`) streams complete frames, and five acquisition restarts in one stream lose none ([#216](https://github.com/VitalyVorobyev/viva-genicam/pull/216)).
- Areas E to J on the same Manta G-125B: every pixel format it offers streams and saves, and a 300 s stream at 30.9 fps (9 265 frames) had no incomplete or missed frame; packet sizes kept, `--auto`, `--packet-size 1000`, and 1600 or 9000 on its 1500-byte link, which the probe bisected down to 1500; its block ids run on across 100 AcquisitionStop/Start in one stream (303 frames, none lost) and across format and width changes; resend requests from the stream socket are answered (3 656 packets asked for and 1 288 recovered in 10 s with a 16 KiB receive buffer at full rate, the rest past each frame's budget), resent packets carry status `0x0000`, and each packet it no longer holds — about 23 frames back — is answered with a header-only `0x800C`; it paces packets by `GevSCPD` only with `BandwidthControlMode` `SCPD` (40 µs: 22 fps; 100 µs: 10.2 fps), and `StreamBytesPerSecond` 30 MB/s holds it to 22.6 fps; a multicast stream and a `--monitor` in a second process both received every frame from the monitor's first whole one; SingleFrame, MultiFrame (5, 12) and Continuous deliver exactly their frames, and its recorder mode takes a record trigger only from Line1 or Line2; 100 software triggers at 10 Hz gave 100 frames; `TriggerDelayAbs`, described for hardware triggers, does not delay a software trigger; `FrameTrigger` events come 3.5 to 5 µs before their frame's timestamp and `ExposureEnd` 99.8 µs after it at a 101 µs exposure; an action command is answered `NOT_IMPLEMENTED` unicast and with silence broadcast; `time_reset` restarts its clock; all 24 tests of the hardware suite pass ([#217](https://github.com/VitalyVorobyev/viva-genicam/pull/217)).
