# viva-genicam 0.10

Releases in the 0.10 series, newest first. The [changelog index](../CHANGELOG.md)
lists every series.

## [0.10.0] - 2026-10-17

The fixes for a Basler a2A4096-44g5m that a reporter could not trigger
([#210]), USB3 Vision on Windows, and stream counters across the Zenoh API.
Read before upgrading:
- **Zenoh API version 6.** `AcquisitionStatus` carries `StreamCounters` in
  `stats` in place of `dropped`. A version 6 service and an older client, or
  the reverse, do not understand each other's status: upgrade `viva-service`,
  `viva-service-u3v` and Viva Studio together.
- **`viva-genapi-xml`:** `NodeDecl::Integer` gains `indexed`, and
  `NodeDecl::Float` gains `value` and `indexed`. Code that builds these
  variants, or matches them without `..`, must name the new fields.

**Not yet run on hardware:** the GenApi fixes below are built from [#210]'s
camera XML and checked against it in the vendor corpus.

### Changed

- **USB3 Vision on Windows.** A camera without the WinUSB driver fails to open
  with an error that names WinUSB and links the book page
  [USB3 Vision setup](https://vitalyvorobyev.github.io/viva-genicam/usb.html#windows),
  which shows how to install it with Zadig. The mvBlueFOX3-2004G runs on
  Windows as well as macOS ([#208]).
- **Zenoh API version 6.** The service sends the stream's counters
  (`StreamCounters`, converted from `viva_genicam::StreamStats` by the
  `genicam` feature) every second while acquiring, whether or not frames
  arrive, and a final status with the stopped stream's counters ([#209]).

### Fixed

- **Indexed values.** An `<Integer>` or `<Float>` that picks its value from a
  table by an index node (`<pIndex>` with `<ValueIndexed>`/`<pValueIndexed>`
  and `<ValueDefault>`/`<pValueDefault>`, GenICam Standard §2.8.5) reads and
  writes the entry its index selects, and takes its bounds, access and lock
  from that entry. An `<Integer>`'s `<pIndex>` was read as an address term:
  on [#210]'s camera, with `TriggerSelector` at `FrameStart` (3), `TriggerMode`
  read bootstrap register 0x000C and reported 1396185518. A command over an
  indexed value, such as that camera's `TriggerSoftware`, completes through
  the selected entry, and a feature whose selected entry is write-only is
  reported without a value instead of being dropped from a snapshot. An index
  that names no entry, on a node with no default, is
  `GenApiError::NoIndexedValue` ([#211], [#212]).
- **A `<Float>`'s `<Value>`** is its value, and a write is kept, as an
  `<Integer>`'s is. Such a `<Float>` had no value, and the converters reading
  it failed ([#211]).
- **A `<StructEntry>`'s own `<pInvalidator>`s** make its cached value stale,
  as its `<StructReg>`'s do ([#211]).
- **rustls 0.23.45 → 0.23.46**, which clears RUSTSEC-2026-0346, -0347, -0348
  and -0349. rustls arrives only through zenoh's QUIC link, so it reaches
  `viva-service`, the release archives that carry it, and Viva Studio
  ([#208]).

### Viva Studio — not part of any published crate

- The Image tab's control panel is an inspector: a label on the left, one
  aligned control column, number fields with the unit inside and no sliders.
  Arrow keys step a value by the camera's increment, and a typed integer
  snaps to it. A control that cannot be changed shows a lock and says why.
  The panel can be resized, and a rail icon opens it at its section ([#209]).
- A **Statistics** section shows the stream's counters: frames received,
  incomplete, missed and dropped by the host; packets and resends for GigE
  Vision; transfers and transfer errors for USB3 Vision; throughput and
  latency. A **Displayed** count sits beside the received one, the header
  says how many frames were lost and why, and the counters stay after Stop
  ([#209]).
- A profile line or ROI stays on the same image pixels when the view is
  zoomed or panned ([#209]).
- The Feature Browser's categories column can be resized, and the search box
  shows one clear button ([#209]).
- Studio's app icon is the viva-genicam mark ([#209]).
