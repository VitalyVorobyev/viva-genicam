# viva-genicam 0.11

Releases in the 0.11 series, newest first. The [changelog index](../CHANGELOG.md)
lists every series.

## [0.11.0] - 2026-10-30

Fixes and features from hardware runs on an Allied Vision Manta G-125B and a
six-sensor GigE Vision camera — exclusive and monitor access, events
acknowledged on arrival, session recovery — plus event-vision blocks in
Python, and frame layout and metadata across the Zenoh API.
Read before upgrading:
- **Zenoh API version 8.** The image header is version 3, with a 24-byte fixed
  prefix: it carries each frame's row stride (API 7, [#221]) and is followed by
  its metadata — frame ID, timestamps, chunks ([#230]). A version 8 service
  and an older Studio, or the reverse, do not understand each other's images:
  upgrade `viva-service`, `viva-service-u3v` and Viva Studio together.
- **`viva-zenoh-api`:** `FrameHeader` gains `row_stride` and `metadata`,
  `FrameHeader::encode` returns a `Result`, and `HEADER_SIZE` and
  `SUPPORTED_VERSION` are 24 and 3. Code that builds a `FrameHeader` must name
  the new fields.
- **`viva-gige`:** `AckSummary` gains `refusals` and is no longer `Copy`.
- **`viva-genapi-xml` and `viva-genapi`:** an integer register whose
  `<pLength>` gives its length has `len` `0` in `NodeDecl::Integer` and
  `IntegerNode`; the length node is `Addressing::length_node`.
  `NodeMap::feature_state` reports a feature whose predicate the camera refuses
  to read as not implemented, not available or locked, where it reported it
  implemented, available and unlocked.
- **`viva-service`:** `DeviceHandle::refresh_connection` takes `&mut self`.
- **`viva-camctl` logs go to stderr**, not stdout; a script that read them
  from stdout must read stderr.
- **The frame delivery queue holds 16 frames, not 4**, so it can hold up to
  four times the payload memory before the oldest frame is dropped.
- **`viva-camctl stream --raw-out` replaces its file**; `--append` adds to it.
- **`Camera::time_calibrate` fits only the offset**, and takes the slope from
  `GevTimestampTickFrequency`; so does `TimeSync::fit` given a frequency.
  Mapped host times follow the camera's reported clock rate, not a slope fitted
  to the samples.

### Added

- **Event-vision blocks in Python.** `FrameStream.next_block()` returns a
  `Frame` for an image and the new `EvsBlock` for an event camera's EVT 3.0 or
  EVT 2.1 data: its bytes as sent, its `format`, timestamps, block ID, status,
  chunks, and the GVSP leader and trailer sizes. `next_frame()` still hands
  event data out as a frame of raw bytes ([#231]).
- **Exclusive access.** `Access::Exclusive` opens a GigE Vision camera with
  exclusive access (CCP `0x1`): while it is held, other applications cannot
  even read the camera. `viva-camctl` takes `--access control|exclusive|monitor`
  on every command that opens a camera, and Python
  `connect_gige(..., exclusive=True)`. On USB3 Vision every open is already
  exclusive, and monitor is refused. The Manta G-125B granted it and answered
  another application's reads with `ACCESS_DENIED` ([#216]).
- **Watching another application's stream from the command line.**
  `viva-camctl stream --monitor` and `bench --monitor` open the camera
  read-only and receive the multicast stream another application set up,
  starting and stopping nothing ([#216]).
- **Python discovery by address.** `vg.discover_ip(ip)` asks one camera
  directly, for a routed subnet that broadcasts do not reach, and
  `vg.discover(allow_broadcast_ack=True)` lets a camera configured for another
  subnet broadcast its answer, as `viva-camctl list --ip` and
  `--allow-broadcast-ack` do ([#216]).
- **Reopening a GigE camera.** `reopen_gige` rediscovers a camera by MAC, opens
  a fresh session and XML, and optionally restores a saved configuration with
  per-feature results. Cancelling an open releases any control already claimed
  ([#218]).
- **Event statistics.** `EventStream::stats` returns `EventStats`: messages,
  acknowledgements, retransmissions, events, and those dropped or malformed
  ([#217]).
- **A GigE Vision hardware smoke suite.**
  `crates/viva-genicam/tests/gige_hardware.rs`, `#[ignore]`d and selected by
  `VIVA_GIGE_IP`, runs the parts of the hardware test plan a test can judge
  against a real camera; see [CONTRIBUTING → Tests](../CONTRIBUTING.md#tests)
  ([#216]).
- **Tested cameras.** The user guide's
  [tested cameras](https://vitalyvorobyev.github.io/viva-genicam/tested-cameras.html)
  page records hardware runs and their evidence, including GenTL checks on a
  real camera through Harvesters and the C consumer ([#218]).
- **Viva Studio: frame timestamps and chunks.** The Image tab shows the exact
  frame ID, device ticks, optional calibrated host time, and XML-decoded chunk
  values and errors of the displayed or frozen image. Standard chunk controls
  stay explicit and respect read-only access ([#230]).
- **Viva Studio: read-only GigE monitoring.** Choose Monitor to inspect
  features and watch an existing multicast stream while another application
  controls the camera; stopping and reconnecting never start or stop its
  acquisition. Discovery requests broadcast acknowledgements and identifies
  cameras on another subnet, with the temporary-IP action in direct mode
  ([#229]).
- **Viva Studio: native camera values.** Freeze a frame to inspect its original
  sample values, histogram and line profile, and save a PNG that keeps its bit
  depth. Bayer inspection uses the sensor mosaic; snapshots are demosaiced
  ([#220]).
- **Viva Studio: an image preview in the Features tab**, to check settings
  without leaving it, sharing the existing preview connection ([#225]).
- **Viva Studio: Image-tab fast controls for older cameras.** Exposure, gain
  and frame rate resolve their legacy standard names and keep the camera's own
  units, ranges and access restrictions ([#225]).

### Changed

- **Events are acknowledged as they arrive.** `EventSocket`, and with it
  `EventStream`, runs a receive thread that acknowledges each message on
  arrival and queues its events, up to `EVENT_QUEUE_CAPACITY` (1024); past
  that the oldest are dropped, logged and counted. The acknowledgement used to
  wait for the application's read, so the Manta G-125B resent events to a slow
  reader and held back the ones behind them
  ([ADR-0033](../docs/adrs/adr0033-event-channel-acknowledges-on-arrival.md),
  [#217]).
- **A camera's reported tick frequency is its clock's slope.**
  `Camera::time_calibrate` fits only the offset, as the median over the
  samples. On the Manta G-125B, frames mapped with a fitted slope drifted from
  their arrival by 14.3 s in 25 minutes; with the reported frequency, by 31 ms
  in 20 minutes ([#217]).
- **The frame delivery queue holds 16 completed frames, not 4**, for GigE
  Vision and USB3 Vision. The six-sensor camera had evicted frames while
  acquisition start returned; with 16, short probes kept frame 1 and tolerated
  a 3 ms consumer pause. The GigE effect was measured on hardware; USB3 Vision
  is covered by fake-camera tests ([#227]).
- **Lower acquisition overhead on Unix.** The GVSP receiver uses bounded socket
  reads and resend writes instead of polling before every packet; Windows
  keeps readiness polling ([#222]).
- **`viva-camctl stream --raw-out` replaces its file**, which it appended to,
  so a rerun added to the previous capture; `--append` adds to it. The file is
  created when the first event block arrives, so an image stream leaves none,
  and `--raw-out` without `--save` no longer also writes `block_0001.*`
  ([#231]).
- **`viva-camctl` logs go to stderr**, so stdout carries only data:
  `viva-camctl dump > values.txt` wrote the Manta G-125B's warnings into the
  file ([#216]).
- **`viva-camctl action` and `send_action` report a refusal.** A camera that
  answers an action command with an error status is listed in the new
  `AckSummary::refusals` (Python `AckSummary.refusals`) and named by
  `viva-camctl action`; it used to be reported as "acknowledged by 0
  device(s)" ([#217]).
- **A predicate that cannot be read is not satisfied.** A `pIsImplemented`,
  `pIsAvailable` or `pIsLocked` whose register the camera refuses now makes
  the feature not implemented, not available or locked, as the GenICam
  Standard defines a predicate by the value it reads. The Manta G-125B's
  `Lens*` features are now not implemented, and the warning is logged once
  per feature. `viva-camctl dump` names on stderr each node it could not read
  ([#216]).
- **A takeover is seen on a camera that does not name its controller.** After
  a write refused with `ACCESS_DENIED`, a camera without GVCP Capability's
  CCP-application bit is asked by claiming control again
  (`GigeDevice::holds_control`), so a session whose control another
  application took reports `ControlState::Lost` at its next write ([#216]).
- **Distribution notices.** Release archives, Python distributions, GenTL
  sidecars and Studio bundles carry target-specific dependency notices
  ([#218]).
- **Viva Studio on macOS** declares why it needs local-network access, and the
  troubleshooting guide separates the app's permission from the CLI's
  ([#218]).

### Fixed

- **An integer register reads the length its `<pLength>` gives.** A
  `<pLength>` on an `<IntReg>` or `<MaskedIntReg>` was read past, leaving the
  default 4 bytes: the Lucid TRT009S event camera's 2- or 8-byte
  `EventExposureStartFrameID` and `EventExposureEndFrameID` read 4 bytes of the
  event. A `<MaskedIntReg>` whose length only a `<pLength>` gives is skipped
  with that reason. Found in the camera's GenApi XML from [#138], now in the
  vendor corpus ([#231]).
- **Chunk mode on a GigE Vision 1.x camera.** The extended chunk payload type
  `0x0005`, which the Manta G-125B sends with `ChunkModeActive` on, is
  assembled as an image with chunks; the stream delivered nothing.
  `Camera::configure_chunks` with no selectors sets chunk mode alone on a
  camera with no `ChunkSelector` ([#216]).
- **An event the camera resends is delivered once.** A copy with the same
  request ID and the same bytes is acknowledged and dropped; distinct events
  under one request ID are each delivered ([#216]).
- **Control ownership on a camera that reverses its primary-application
  registers.** The six-sensor camera stores the controller's IP and port in
  the opposite layout; ownership accepts it when both values name our socket,
  so acquisition no longer reports a false control loss ([#224]).
- **GigE session recovery.** `viva-service` replaces the whole served handle
  after control loss or an address or interface change, with fresh XML and
  connection metadata ([#218]).
- **Stale control routes after FORCEIP.** A send that fails with
  address-unavailable reconnects the existing UDP socket before retrying,
  keeping its port and transaction ID. Whether this cures the link-local
  failure seen on hardware is still open ([#218]).
- **A refused resend packet no longer cancels its neighbours.** Only the named
  packet stops retrying; it used to close the whole missing range ([#219]).
- **An odd pixel count in a bit-packed format converts.** The Manta G-125B's
  1291 × 963 `Mono12Packed` frames stop inside the last packing group, and
  `viva_pfnc::convert` refused every one as a byte short ([#217]).
- **A short GigE Vision `10Packed` image is refused** instead of returning
  too few samples, or panicking in `to_rgb8` on `BayerRG10Packed` ([#218]).
- **The frame rate is the camera's.** `StreamStats::avg_fps` and `avg_mbps`
  are measured from each frame's last packet, not from when the application
  took it: `viva-camctl bench` reported 10 742 fps for a 30.9 fps camera
  whose frames were handed over in a burst ([#217]).
- **`GevSCPSPacketSize`'s do-not-fragment flag is kept** when a packet size is
  set, and the packet-size probe puts it back as it found it ([#217]).
- **An action command to a subnet's broadcast address is sent** on macOS,
  where it failed with `Permission denied` ([#217]).
- **`viva-camctl list --allow-broadcast-ack` and `report` find a camera
  configured for another subnet on macOS**: discovery binds the unspecified
  address so the broadcast acknowledgement reaches it ([#215]).
- `viva-camctl bench --monitor` reports its mode as `monitor` in `--json-out`
  ([#217]).
- **Remote padded images.** Services keep each row's padding and send its
  stride, so Studio's preview and native capture use the right rows; odd
  packed and subsampled images keep their last pixel group ([#221]).
- **Remote feature-state queries.** The single-feature handler no longer
  answers the bulk-state endpoint, so Studio's polling no longer draws
  duplicate error replies and warnings ([#224]).
- **Viva Studio detects a lost direct camera.** GigE sessions recover by MAC
  with fresh XML and controls; acquisition stays stopped until Start. A camera
  whose control was taken stays read-only rather than being reclaimed.
  Disconnected USB cameras offer manual reconnection ([#228]).
- **Viva Studio controls after remote recovery.** A replacement session
  refreshes the feature cache, restoring controls without a manual reconnect;
  a delayed replacement cannot undo a disconnect ([#225]).
- **Viva Studio preview cadence near its display limit.** Deadline pacing no
  longer takes every second frame from a camera just above the preview rate
  ([#225]).
- **Viva Studio's fallback XML model** honours imposed access limits ([#218]).
- **Private bench evidence is anonymous.** Documentation and code comments omit
  private device names and identifiers, and distributed packages carry no raw
  captures or device descriptions ([#228]).

### Run on hardware

- On the Allied Vision Manta G-125B (firmware 00.01.44.28514, GigE Vision
  1.2): a command register clears by the first `IsDone` read; `WriteAround`
  registers read back the value just written; a second application's claim
  and writes are refused with `ACCESS_DENIED` while one holds control; a saved
  configuration loads back to the same 98 values; every pixel format it offers
  streams complete frames, and five acquisition restarts in one stream lose
  none. A monitor received 123 frames while the controlling multicast stream
  received all of its 308. All 19 tests of the hardware suite passed ([#216]).
- Areas E to J on the same camera: a 300 s stream at 30.9 fps (9 265 frames)
  with no incomplete or missed frame; packet sizes kept, `--auto`, and the
  probe bisecting 1600 or 9000 down to its 1500-byte link; block IDs running
  on across 100 AcquisitionStop/Start and across format and width changes;
  resend requests answered, and a packet it no longer holds answered with a
  header-only `0x800C`; packet pacing by `GevSCPD` with `BandwidthControlMode`
  `SCPD`, and by `StreamBytesPerSecond`; SingleFrame, MultiFrame and
  Continuous delivering exactly their frames; 100 software triggers giving
  100 frames; an action command answered `NOT_IMPLEMENTED` unicast and with
  silence broadcast; `time_reset` restarting its clock. All 24 tests of the
  hardware suite passed ([#217]).
- On the six-sensor camera: Studio's native quick controls, compact preview,
  near-cap cadence and controls after a software reset passed short checks.
  Delivery probes located small-ROI loss before the first consumer read, and
  preloading NumPy avoided cold-import drops. See the
  [bench record](../docs/hardware-six-sensor-2026-10-26.md#studio-and-delivery-follow-up-2026-10-27)
  ([#226]).
