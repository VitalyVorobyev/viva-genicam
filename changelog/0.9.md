# viva-genicam 0.9

Releases in the 0.9 series, newest first. The [changelog index](../CHANGELOG.md)
lists every series.

## [0.9.0] - 2026-10-13

0.9.0 is the capability-gaps release: it fixes every item that [#191] planned
for it. JPEG, multi-part and GenDC payloads are still counted, not assembled.
It is a breaking release; read the list below before upgrading.

**Tested only against the fake cameras:** the GVSP receive engine, packet
resend, the GigE Vision chunk and event layouts, and the GigE session
lifecycle. We do not have the GigE Vision standard's text, so these follow
what Wireshark's dissector, aravis and the vendor XML agree on. The GenTL
producer is tested with Harvesters, against the fake GigE camera.

**Run on hardware:**
- **USB3 Vision ran on one camera**: a MATRIX VISION mvBlueFOX3-2004G, on macOS
  arm64 over USB 2 High Speed ([#205], [ADR-0032] §8). Checked on it:
  streaming, chunks, events, host time, endpoint resets and an unplug, plus
  [#206]'s GenApi and persistence fixes, Python, and `viva-service-u3v`.
  Untried: Linux, Windows, SuperSpeed, other vendors, and a transfer failing
  mid-stream. On Linux or Windows, please run the hardware suite
  ([CONTRIBUTING](../CONTRIBUTING.md#tests)) and send
  `viva-camctl report --usb 0`.
- **[#163]**: a reporter saw a Micro-Epsilon scanCONTROL 8500-50 keep control
  while a command was pending, and answer no CCP read sent meanwhile. The
  library does not wait for those answers.
- **Earlier reports**: the extended-ID fix rests on a LUCID TRT009S-E capture
  ([#139]). The chunk-port fix likely explains [#112]'s `BAD_ALIGNMENT` errors,
  not yet confirmed on that camera.

### Read before upgrading

- **`Frame` is `#[non_exhaustive]`** (build with `Frame::new`) and gains
  `block_id`, a 16-bit `payload_type`, `status`, `padding_x` and
  `row_stride()`; `EvsBlock` gains `block_id` and `status`. Streams deliver
  only complete frames unless asked (`set_deliver_incomplete`).
  `set_frame_timeout` is `set_block_timeout`, timed from a block's last packet.
  `viva_pfnc::convert` takes a `row_stride`. ([#194], [#198])
- **`StreamStats` is rewritten** as `viva_genicam::StreamStats` for both
  transports, counting every frame once: `drops` is `frames_lost()`, the
  `resend_*` counters replace `resends`, `U3vFrameStream::dropped()` is
  `stats()`; `bench --json-out` reports these. ([#194], [#195], [#205])
- **A GigE stream binds a port that the OS picks**, not 24575 (10040 in
  `viva-camctl`). Behind a firewall, set `destination_port` or `--port`.
  `GevSCPD` is written only when asked, as a `Duration`. `StreamParams` gains
  `channel`, `camera` and an optional `packet_delay`. ([#195])
- **Errors carry typed causes, and every error enum is `#[non_exhaustive]`**
  ([ADR-0030]). `GenicamError::Transport` and `Parse` become `Gige`, `U3v`,
  `Network { during, source }` and `Xml`, and the facade's refusals get
  variants such as `NotInControl` and `MissingFeature`. `GenApiError::Parse`
  splits into `RegisterEncoding` and `Declaration`. `Access`, `Type` and
  `Range` have typed fields, and a node with nothing to read is
  `NoValueSource`. New: `EnumEntryUnavailable` (such an entry used to be
  written), `BadLength`, `NotAttached`, `PortNotWritable`; `TimeError` is gone.
  ([#197], [#199], [#203], [#206])
- **Status codes are per transport** ([ADR-0020]). `viva_gencp::StatusCode`
  holds only the shared codes, has no `Unknown`, and `from_raw` returns an
  `Option`. GigE errors and `FrameStatus::DeviceStatus` hold a `GigeStatus`,
  and USB3 Vision errors a `U3vStatus`. ([#203])
- **Modules are private, and crate roots re-export what is public**
  ([ADR-0030]). `viva_gige::{gvcp,gvsp,nic,…}::X` is `viva_gige::X`, with
  constants in `viva_gige::consts`. `viva_genicam::{stream,frame,…}::X` is
  `viva_genicam::X`, and `viva_u3v`'s offsets are in `viva_u3v::registers`.
  `viva-genapi`'s node caches and addressing are private
  (`NodeMap::register_address`). More types, the XML declarations among them,
  are `#[non_exhaustive]`. ([#203])
- **`Camera`'s transport-specific methods compile only for their transport.**
  For example, `configure_stream_multicast` is on `Camera<GigeRegisterIo>`.
  `set_exposure_time_us`/`set_gain_db` are `set_exposure_time`/`set_gain`, in
  the feature's own unit. `get` on a category and `set` on a command are
  errors. Python follows. `acquisition_start` sets `TLParamsLocked`, so `Width`
  refuses writes while acquiring. ([#199])
- **GenApi writes what the XML declares.** A command writes its
  `<pCommandValue>` (19 of 38 corpus documents); `1` used to be written. A
  value outside `<Min>`/`<Max>`/`<Inc>`, or their `<p…>` forms, fails with
  `Range` before it is sent. Values are cached only as `<Cachable>` allows, and
  enumeration entries keep the XML's order. `NodeMap::set_string` and
  `set_register` take `&mut self`. ([#193], [#199], [#201])
- **The XML model** (`viva-genapi-xml`): bounds are `Option`s, with `p_inc`,
  `p_min` and `p_max`; `<pPort>` is part of `Addressing`.
  `Command::command_value` is a `CommandValueSrc`, `Boolean`/`Enum` gain
  `value`, and `NodeMeta` gains `cachable`, `polling_time_ms` and `ignored`. A
  `<String>` is no register (`StringDecl::addressing` is an `Option`);
  `Addressing::Sum` gains `p_length`. ([#193], [#197], [#199], [#201], [#206])
- **Chunks and events are read through the camera's XML** ([ADR-0026]).
  `ChunkKind`, `ChunkMap`, `parse_chunk_bytes` and `Frame::chunk` give way to
  `Frame::chunks` and `Camera::with_chunks`; with chunks, `Frame::payload` is
  the image alone. `parse_chunks` reads the GigE Vision layout and returns a
  `Result`. `Event` gains `stream_channel`, `block_id` and `raw`, and its
  `ts_host` is `None` until `time_calibrate` fits the clock. ([#197], [#203])
- **Dropping a GigE camera releases control**, and opening one that another
  application controls is refused: open it with `Access::Monitor` (Python
  `monitor=True`). `GigeRegisterIo::new` expects a device holding control.
  Discovery stops asking for broadcast answers (`DiscoveryOptions` opts in).
  `gvcp_capability` returns a `GvcpCapability`, `mtu` an `Mtu`. ([#198])
- **`viva-camctl`**: `get-usb`, `set-usb` and `stream-usb` are now `get`, `set`
  and `stream` with `--usb N`. `get` opens the camera read-only. `describe`
  fails when it cannot read a feature's state. ([#198], [#200], [#201], [#205])
- **Python's `Frame.to_numpy()` keeps the camera's depth**: 10- to 16-bit
  formats, packed ones included, are `(H, W)` `uint16`. A Bayer frame is its
  mosaic, and `to_numpy(demosaic=True)` gives the RGB that a `Bayer*8` frame
  gave before. `U3vDeviceInfo.bus` is a `str`. ([#202], [#205])
- **Zenoh API version 5.** `viva_zenoh_api::PixelFormat` is replaced by
  `viva_pfnc::PixelFormat`, and `image/meta` uses PFNC names (`RGB8Packed`, not
  `RGB8` or `Unknown`) ([#196], [#203]). Payloads are `#[non_exhaustive]` with
  constructors, `AcquisitionStatus.dropped` counts every frame not delivered
  complete ([#194]), and `FeatureState` gains `polling_time` and `caching`
  ([#201]). `viva-service`'s library is the service, not its modules ([#203]).
- **USB3 Vision uses `nusb`, not libusb** ([ADR-0032]). `RusbTransfer` is
  `NusbTransfer`, `U3vDeviceInfo::bus` is text and loses `interface_info`, and
  the Python package is `MIT`-licensed. A device id names the serial
  (`cam-u3v-164c5533-FF003089`), so identical cameras differ; a byte other than
  a letter, digit, `-` or `.` becomes `_` and two hex digits. ([#203], [#205],
  [#206])
- **The USB3 Vision stream is rebuilt** ([ADR-0032]). `U3vStream` is no longer
  generic, and `RawFrame::trailer` is an `Option`. On a USB3 Vision camera,
  `Camera::open_stream` takes `U3vStreamOptions`, and `U3vStreamBuilder::new`
  takes `camera.transport()`. ([#205])

### Added

- `Camera::open_stream(StreamOptions)` opens a GigE stream in one call; Studio,
  the services, `viva-camctl` and Python use it. `FrameStream` gains blocking
  reads and incomplete frames on request. ([#194], [#195])
- **Packet resend** ([ADR-0025]) is on where a camera offers it. Turn it off
  with `ResendPolicy::Off`, `--no-resend` or `resend=False`. ([#195])
- **Chunk and event features**: `Camera::with_chunks`, `chunk_features`,
  `with_event` and `event_features` ([ADR-0026]). ([#197])
- **GigE monitors and discovery**: read-only monitors that can watch the
  controller's multicast stream, and `control_state` with `reclaim_control`.
  `discover_ip` and `list --ip` find one camera, and `list` flags a camera on
  another subnet. `PENDING_ACK` is enabled where a camera offers it. ([#198])
- **Facade helpers**: typed accessors, helpers for exposure, gain, triggers,
  ROI, binning, frame rate and user sets that accept older names, and
  `viva_genicam::blocking` for code without async ([ADR-0027]). ([#199])
- `Camera::execute_and_wait` and `is_done` (GenICam `IsDone`);
  `viva-camctl execute` and Python's `execute` wait by default. ([#193])
- **Save and restore a configuration** ([ADR-0028]): `save_features` and
  `load_features` in Rust and Python, and `viva-camctl save`/`load`. A load
  reports what it could not write. `viva-camctl` also gains `features`,
  `describe`, `dump`, `read-reg`, `write-reg` and `action`. ([#200])
- **Polling and refresh** ([ADR-0029]): `<PollingTime>`,
  `Camera::changed_since` and `poll`. ([#201])
- **Pixel formats**: packed, 10/12-bit Bayer and Y'CbCr formats,
  `viva_pfnc::convert` (which `Frame::to_rgb8` uses, demosaicing bilinearly)
  and 16-bit PNG/TIFF output (`image-io`). ([#196])
- **Python parity**: typed features, helpers, chunks, events, frame status,
  stream counters, action commands, monitors that stream, and checked type
  stubs. `viva_genicam.testing.FakeU3vCamera` is new. ([#202], [#203])
- `viva-service-u3v` rescans, serves every USB3 Vision camera, and reports one
  that leaves as disconnected. ([#203])
- **A GenTL producer, `viva_gentl.cti`**, on each release: GenTL consumers such
  as Harvesters use GigE Vision cameras through it ([ADR-0031],
  [guide][gentl]). ([#204])
- **USB3 Vision streams that recover** ([ADR-0032]). Eight transfers are in
  flight, a failed transfer costs one frame, and an unplug ends the stream with
  `U3vError::Disconnected`. Chunks, events, counters and host time use GigE
  Vision's types, and `stream`, `events`, `chunks` and `bench` take `--usb`.
  Full-ROI rate on the mvBlueFOX3-2004G: 113.5 fps, up from 106.7. ([#205])
- **`<pLength>`** for `<Register>` and `<StringReg>`, and `NodeMap::ignored()`,
  which lists the elements the parser read past. ([#206])

### Changed

- **One GVSP receive engine on every OS** ([ADR-0025]). A thread per stream
  reads the socket, and a four-frame queue drops the oldest frame (and counts
  it) when the application falls behind. ([#194])
- `<pSelected>` is read on the selector, and `execute_and_wait` polls at a
  command's `<PollingTime>`. ([#193], [#201])

### Fixed

- **GVSP assembly**: a frame taking over 100 ms never completed, extended-ID
  streams were assembled 12 bytes off per packet, an early trailer or repeated
  leader cost the frame, and Windows truncated packed formats. ([#194])
- **GigE streams**: two streams on one host shared a port, a frame of short
  packets passed as complete, and macOS never chose jumbo frames. ([#195])
- **Chunk and event ports**: 518 registers in 19 corpus documents read device
  memory, and chunk data was looked for in the trailer. ([#197])
- **GigE control**: multicast setup set don't-fragment and misplaced the port;
  an ICMP error re-sent a pending command; padded rows were shifted. ([#198])
- **Pixel formats**: 16-bit Bayer formats had other formats' codes. ([#196])
- **GenApi**: a floating `<Integer>` could not be written ([#193]), nor a
  register-less `<Boolean>` or `<Enumeration>` read or written ([#199]). A
  register addressed through an embedded `<IntSwissKnife>` had no address
  ([#205]), and a `<StructEntry>` lost its `<StructReg>`'s visibility ([#206]).
- **Strings**: a `<String>` with `<pValue>` or `<Value>` read empty, as did a
  `<StringReg>` with `<pLength>`. ([#206])
- **Saving**: nested selectors were saved under one entry ([#201]); a feature
  behind a selector that cannot be set was dropped, and selectors moved
  needlessly ([#206]).
- **Threads**: a camera opened from a current-thread Tokio runtime panicked
  ([#199]), as did a Python camera used from a second thread ([#202]) and a
  Python USB3 Vision stream at open ([#203]).
- **Status codes**: a USB3 Vision status printed as `Unknown(32779)`. ([#203])
- **USB3 Vision**: a stream could start with an earlier acquisition's data,
  discovery could not describe a camera another program held, and
  `time_calibrate` missed GenCP's `Timestamp` ([#205]). An event reader retried
  cancelled transfers forever ([#206]).
- **Services**: `viva-service` returned before a command finished ([#199]), and
  kept publishing a lost camera's frames ([#205]).
- **Output**: GenTL buffers misreported endianness, delivered height and size
  ([#205]), and `viva-camctl` printed an error's cause twice ([#206]).

### Removed

- `GigeDevice::request_resend`, whose request matched neither Wireshark nor
  aravis ([#195]). `Stream::socket()`, `FrameStream::socket()` and the unused
  reassembly types ([#194]). `viva_sfnc::MULTICAST_ENABLE` ([#198]), the
  non-standard `<Selected>` addressing ([#193]), and unused `viva_gige` and
  `viva_gencp` items such as `encode_cmd` ([#203]).

### Viva Studio and documentation — not part of any published crate

Viva Studio (`studio/`) is not published to crates.io; its desktop bundles are
attached to the GitHub release. Nothing in this section changes the library.

- Studio re-reads the features on screen at their polling time ([#201]), also
  after they come back into view ([#202]).
- Its command button waits for the command to finish ([#199]). The Linux
  bundles need glibc 2.39 or newer ([#192]); no bundle links libusb ([#205]).
- The user guide gains *Common tasks* ([#199]), *The command line* ([#200]) and
  *Use viva from other tools* ([#204]); its Python part is rewritten ([#202]).
